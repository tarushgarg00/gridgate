# GridGate

A first-pass site screener for data center development. Enter a U.S. location and GridGate assembles the early diligence picture, scores the site against a buy box, surfaces deal-killers first, and stops at the line where human judgment takes over.

I built it to understand, from the inside, the problem that [Build](https://build.inc) solves at real scale. GridGate does a small fraction of what their platform does, on a handful of public data layers instead of the 1,600+ they work with. Building even this much made clear why the real thing needs an agent architecture and a domain team.

---

## Why this exists

Before anyone commits capital to a data center, a team spends weeks answering a brutal set of questions: can you actually get power, how long is the queue, is there water and fiber, does zoning work, and will the community accept it. Most of that work is information assembly across fragmented public sources, and one bad answer can cost millions and years.

GridGate automates a narrow slice of that first-pass screen. It is deliberately focused and deliberately honest about where it stops.

## The one idea

**Shallow everywhere except power.** Most layers, including flood, wetlands, fiber, land cover, and zoning, are quick first-pass signals. One layer, power and grid interconnection, goes deeper because power is the constraint that most often kills these deals. The asymmetry is the point: a useful first-pass tool should spend its depth on the gate that matters most.

## What it does

- Takes a U.S. address or coordinates and assembles a one-screen **site brief**.
- Produces a **measured buy-box score** and a verdict: Advance, Conditional, or Do Not Advance.
- **Surfaces deal-killers first**, such as a FEMA high-risk flood zone, and hard-caps the score when one is present.
- Goes **deep on power**: nearest high-voltage transmission line and distance, nearest substation and voltage, regional interconnection-queue pressure and typical wait, grid mix, and industrial electricity price.
- **Traces every datapoint to a primary public source** through inline source tags. No black boxes.
- **Stops at the human-review line.** Power negotiation, community and permitting, land cost and availability, and capital structure are explicitly not automated.

## What it deliberately does not do

This is the most important section. GridGate scores what it can measure from public data and refuses to over-claim on what it cannot.

- It does **not** assess land cost, parcel availability, or zoning suitability. These are often the real disqualifiers. A dense urban site can have excellent infrastructure and still be impossible, so the tool flags those conditions for human review instead of pretending to solve them.
- It does **not** confirm available load. A nearby transmission line means proximity, not megawatts you can draw. Securing load requires a utility study and negotiation.
- The interconnection-queue signal is **regional context**, not a site-specific queue position.

Calling these out is intentional. The judgment line is exactly where a tool like this should hand off to people.

## Design philosophy

**Deterministic core, AI at the edges.** Every score, distance, and flag is computed deterministically from public data in unit-tested functions. The optional plain-English summary is generated by an LLM that only rephrases the deterministic output; it never produces a number.

**Built to read like a diligence memo, not a generic SaaS screen.** The interface uses an editorial layout, restrained color, and monospace data/source tags to make auditability visible.

## Data sources

| Layer | Source |
| --- | --- |
| Geocoding | U.S. Census Geocoder |
| Transmission lines, substations | HIFLD Open Electric Power Transmission Lines and Electric Substations |
| Interconnection queue context | LBNL Queued Up dataset |
| Grid mix, retail price | EIA API v2 |
| Flood | FEMA National Flood Hazard Layer |
| Wetlands | USFWS National Wetlands Inventory |
| Land cover | USGS NLCD / MRLC |
| Fiber / connectivity | PeeringDB |
| Basemap | MapLibre GL JS + MapTiler |
| Narrative, optional | Anthropic API |

## Tech stack

Next.js App Router, TypeScript, Tailwind CSS, MapLibre GL JS, Turf.js for geospatial math, Recharts, and Vitest.

## Running locally

```bash
npm install
npm run dev
```

The app runs with **zero API keys** using three bundled example sites. Data that cannot be fetched live degrades to an explicit unavailable/manual-review state rather than silently failing.

To enable live lookups and the AI narrative, create `.env.local`:

```env
NEXT_PUBLIC_MAPTILER_KEY=    # maps - cloud.maptiler.com
EIA_API_KEY=                 # grid data - eia.gov/opendata
ANTHROPIC_API_KEY=           # optional narrative - console.anthropic.com
```

```bash
npm run test
npm run build
```

## Example sites

Three cached examples demonstrate the scoring and work with no keys:

- **New Albany, OH** - Advance. Strong infrastructure in an established data-center market.
- **Lebanon, IN** - Conditional. Looks viable on the surface, but the power layer flags regional queue pressure and time-to-power risk.
- **New Orleans, LA** - Do Not Advance. A FEMA flood deal-killer overrides otherwise reasonable infrastructure.

## Honest scope

This is a prototype built solo in a short window to think through a real problem, not a production site-selection product. The data is real and the logic is deterministic and tested, but the coverage is intentionally narrow, the queue data is regional rather than parcel-specific, and the hardest parts of site selection, including land, zoning, power negotiation, and community acceptance, remain human judgment by design. That boundary is the part I find most interesting.
